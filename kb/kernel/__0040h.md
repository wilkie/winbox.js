## Observed behaviour

- [[read out]] `KRNL386.EXE`'s entry table holds 0040h at this ordinal, in segment FEh, a constant. KERNEL puts a protected-mode selector for that paragraph there as it starts.
- [[measured]] [[probe:kconst]]: a selector in the local table at privilege 3 for a data segment of 64 KiB, writable and not yet accessed (`LAR` F200h). Its base is 400h above [[fn:KERNEL.__0000H]]'s. [[fn:KERNEL.GetProcAddress]] answers it with FFFFh in the high word.
- [[inferred]] Selector 40h, which DOS's extender keeps in the global table, reaches the same memory. winbox.js keeps both, and they reach the same memory here too.

## Implementation

The selector is one of the nine below the interrupt descriptor table's, which no block is given, and its base is in the megabyte winbox.js keeps for the first megabyte at FFE00000h. Both engines write it where a program imports it, as KERNEL's loader writes a constant. See [[topic:exported-constants]].
