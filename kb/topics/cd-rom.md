Programs of the time find their CD-ROM by asking MSCDEX through `INT 2Fh`, then read its files through DOS like any drive's. Under DOSBox, where the oracle's Windows runs, a disc is an image mounted with `IMGMOUNT -t iso` -- an `.iso`, a raw `.bin`, or a `.cue` sheet of tracks (see [[topic:drives-and-disks]], "Disk and CD images", for how the probes mount one and the design that will mount one here).

## MSCDEX

- [[measured]] [[probe:mscdex]], with no disc: 1500h answers AL FFh -- installed -- BX 0 drives, CX as it was; 150Bh answers AX 0 and BX ADADh for every drive; 150Ch BX 0217h, version 2.23; 1100h AL FFh.
- [[measured]] [[probe:imgcd]], a disc as D:: 1500h BX 1, CX 3 (D:, from nought for A:); 150Bh AX 5AD8h for D:, nought for the others.
- [[read out]] DOSBox installs its own MSCDEX whether or not a disc is mounted (`dos_mscdex.cpp` 1312-1322).
- Both engines answer these four as DOSBox does, a drive removable and remote counted a CD-ROM ([[topic:drives-and-disks]], "MSCDEX").

## The drive

- [[measured]] [[probe:imgcd]]: IOCTL 4408h is error 1; 4409h DX 1000h, remote; 440Dh and 440Eh error 1; `GetDriveType` 4, `DRIVE_REMOTE`. [[read out]] `isoDrive` is remote and removable (`drive_iso.cpp` 374-380), and `SYSTEM.DRV` takes a remote drive for `DRIVE_REMOTE` before asking anything else.
- [[measured]] 36h: 1 sector to a cluster, nought free, 2,048 bytes to a sector, 60,000 clusters, whatever the disc.

## The disc's files

- [[measured]] Names lose their `;1` and a trailing dot, are cut to eight characters before the dot and twelve in all, and are listed in capitals, in the disc's order. The root has no `.` and `..`; a folder lists them first. A folder whose name was cut cannot be entered by either name.
- [[measured]] A file is found by its listed name, its whole name, in either case.
- [[measured]] Attributes listed: 20h a file, 10h a folder, 02h added where the record is marked hidden. 4300h adds read-only: 21h, 23h, 31h.
- [[measured]] Stamps are the record's own, the offset from GMT ignored.
- [[measured]] The label search answers the volume's name made 8.3 with a dot: `WINBOXCD.202` for `WINBOXCD2026`.
- [[measured]] Making, deleting and renaming a file answer error 2, making a folder error 3.
- [[measured]] A name DOS will not take is refused before the disc is asked: `README.TXT;1` is error 3, path not found. [[read out]] `DOS_MakeName` (`dos_files.cpp` 58-180) takes letters, digits, the punctuation ``\$#@()!%{}`~_-.*?&'+^`` and five bytes above 7Fh, drops spaces, and refuses anything else with error 3, and a name with a second dot after its first with error 2 (3 for a folder's); it cuts each name to eight characters before its dot and three after, so `A_VERY_LONG_FILE_NAME.TEXT` reaches the disc as `A_VERY_L.TEX` and `LONGNAMEDFOLDER` as `LONGNAME`, which no record's twelve characters match.

## Cue sheets and raw images

- [[measured]] [[probe:imgbin]], [[probe:imgcue]], [[probe:imgcue2]] and [[probe:imgtrk]] run `imgcd`'s records with the same disc as D: in four other forms: `imgcd.bin`, its sectors as raw 2,352-byte mode 1 ones (sync, header, data, EDC), mounted as it is; `imgcd.cue`, a sheet of one `MODE1/2352` track in that file; `imgcd2.cue`, one `MODE2/2352` track in `imgcd2.bin` (mode 2 form 1); and `imgtrk.cue`, two files -- the data track in `imgcd.bin`, then after a two-second `PREGAP` an `AUDIO` track in a `WAVE` file, `imgtrk audio.wav`, its name quoted with a space, with `REM`, `CATALOG` and `TITLE` lines. Each answers all 91 records as `imgcd` does (the one record that differs in `imgcue2`, 440Dh's DX, is the probe's own buffer, two bytes further on in a longer name's build).
- [[read out]] What is mounted is the disc's sector 16, counted from the first track's start, whatever track it is in: a sheet whose first track is audio, or whose first track has a `PREGAP` before it, has no volume there, and DOSBox refuses it as a corrupt image (`drive_iso.cpp` 175).

## Inside DOSBox

[[read out]] `isoDrive` (`drive_iso.cpp`), with its image read through `CDROM_Interface_Image` (`cdrom_image.cpp`):

- **The track.** An `.iso` is one data track whose sectors are the first of four layouts with a primary volume descriptor at sector 16: 2,048-byte sectors, 2,352 with the data 16 bytes in, or mode 2's 2,336 or 2,352 with it 24 in (`LoadIsoFile`, `CanReadPVD`, 350-404). A sector past the image's whole sectors is not read. Sector 16 must be type 1, `CD001`, version 1, and its root record readable, or the image is not mounted (`loadImage`, 516-526). No other descriptor is looked at: no Joliet, no Rock Ridge.
- **A record** (`readDirEntry`, 476-514) is copied over the one read before it, as many bytes as its first says. One with extended attributes, interleaving, a name longer than the record or than 200 bytes is not read -- and ends its folder's listing and lookup there, since `GetNextDirEntry` then answers false. A folder's own two are `.` and `..`; a file's name ends at its first `;`, loses a dot at its end; then any name is cut to eight characters before its first dot when that dot is further in, and to twelve.
- **Searching.** A folder is read through one of the drive's 2,048 directory iterators, taken in turn and let go as a search ends (`GetDirIterator`, `FreeDirIterator`, 390-452); its number is kept in the search's record, the word at 0Dh. `FindFirst` (250-284) looks the folder up -- folder or not -- and takes an iterator; with the label's attribute alone it answers the label, wherever it is asked, or no more files where the disc has none; with the label's among others, in the root, the label first where the pattern takes it. `FindNext` (286-323) passes over `.` and `..` in the root, and a folder or hidden record not asked for; a name is listed upper case, its size its data's length, 10h a folder else 20h, with 02h where the record's existence bit is set.
- **Looking up** (`lookup`, 528-562) goes from the root, name by name, a dot at the end of each taken off, comparing at most 37 characters without regard to case.
- **Files.** `FileOpen` (204-223) refuses a file opened to write alone, access denied -- and DOS's `DOS_OpenFile` then answers 5 where the file is there; a file opened to read and write is opened, but every write fails. Reads stop at the end of the file, a seek outside it puts it at its end (`isoFile`, 63-123). A file's stamp is its record's, packed by `DOS_PackDate` and `DOS_PackTime` with their masks (`dos_inc.h` 220-226). 4400h answers 40h with the drive (`GetInformation`, 130-132). 4301h on a disc is access denied before the file is looked for (`DOS_SetFileAttr`, `dos_files.cpp` 643-656).
- **The image** (`CDROM_Interface_Image`, `cdrom_image.cpp`). `SetDevice` (167-178) reads the file named as a cue sheet first (`LoadCueSheet`), and only where that fails as one data track (`LoadIsoFile`) -- so an `.iso` or a `.bin` is read as a sheet too, which a binary file fails at once. `isoDrive` reads every sector cooked through `ReadSector` (301-313): the track the sector is in found by `GetTrack` (287-299), from each track's start to the next's, the lead-out no track; the sector `skip + (sector - start) * sectorSize` into its file, 16 further for a raw sector, 24 for a mode 2 one. Nothing checks a sector's sync, header, mode or EDC.
- **A cue sheet** (`LoadCueSheet`, 422-556) is read a line at a time by `getline` into 512 bytes: a line longer than 511 fails the sheet ("probably a binary file"), and a line is read only to its first nought. Its first word, upper-cased (`GetCueKeyword`), is the command: `TRACK n type`, its type one of `AUDIO`, `MODE1/2048`, `MODE1/2352`, `MODE2/2336` and `MODE2/2352` -- any other, `MODE2/2048` or `CDG` among them, fails the sheet; `INDEX 1` its start, `INDEX 0` where its pregap in the file begins, other indexes passed over; `PREGAP` a gap not in the file; `FILE name type`; `CATALOG` the disc's number; `CDTEXTFILE`, `FLAGS`, `ISRC`, `PERFORMER`, `POSTGAP`, `REM`, `SONGWRITER` and `TITLE` passed over -- `POSTGAP` taking no room -- and any other command fails the sheet, `ARRANGER`, `COMPOSER` and `MESSAGE` among them, and a first word with a UTF-8 byte-order mark before it. Times are `%d:%d:%d`, minutes, seconds and frames of 75 to a second (`GetCueFrame`, `MSF_TO_FRAMES`).
- **A `FILE`'s name** (`GetCueString`, 668-684) is the next word; one beginning with a quote is read again from the quote to the next, at most 255 bytes where it has a space in it. Its type is `BINARY`, or an audio file's: `WAVE`, `AIFF` and `MP3` by name, or any decoder's first extension in the `SDL_sound` the build links (515-525) -- [[measured]] for the oracle's `libSDL_sound` 1.0 `MP3`, `669`, `WAV`, `AIFF`, `AU`, `OGG`, `VOC`, `RAW`, `SHN` and `FLAC`; any other type, `MOTOROLA` among them, or a file not opened, fails the sheet. The file is found by `GetRealFileName` (618-647): the name as given, from DOSBox's working folder; else the cue sheet's folder and the name joined; else the name as a DOS path through DOSBox's own mounted folders. On Linux each is the host's `stat`, so case counts.
- **The tracks' layout** (`AddTrack`, 558-606). The first track must be number 1, each after it the next number. A track in the same file as the one before starts at its `INDEX 1`, the one before ending there, less its `INDEX 0` gap; a track in another file starts after the whole of the one before's file, its last sector counted where it is cut short. An `INDEX 0` at `00:00:00` is no gap at all (`prestart > 0`), so a track of its own file whose `INDEX 1` is `00:02:00` starts 150 sectors on with its file read from its first byte. Each `FILE` opens a file of its own, even one named twice, so two tracks in one file named twice are laid out as in two files. A lead-out ends the list.
- **A file's stream** (`BinaryFile`, 47-72) is an `ifstream`: a read past its end fails, and leaves the stream failed, so that every read of that file after it fails too (`seekg` does nothing on a failed stream).
- **The label** is the volume's name as MSCDEX reads it -- sector 16's bytes from 40, at most 31, white space at the end taken off (`GetVolumeName`, `dos_mscdex.cpp` 561-597) -- made by `Set_Label` with `cdrom` true (`drives.cpp` 80-108): eight characters, a dot, three, case kept, and a dot left at the end where it is the ninth.

## In WinBox

- An ISO 9660 image is `IsoVolume` (`crates/winbox-machine/src/files/iso.rs`) and `ISO9660` (`src/file-systems/iso9660.ts`), each `isoDrive`'s functions by their names: the track found as `LoadIsoFile` finds it, records copied over one another, the 2,048 iterators taken and let go in turn, `lookup`, `FindFirst`, `FindNext`, `GetFileAttr`, `isoFile`'s reads and seeks. Its search is begun by `Volume::find_first` / `ISO9660.findFirst` and carried on through the iterator its record names (`find_from`).
- Both engines' DOS follows `DOS_MakeName` on an image's drive, a disc's or a FAT's (`dos_name` and `make_name_error` in `dos.rs`; `dosName`, `makeNameError` and `refusedName` in `src/dos/syscall/directory.ts`), and opens the name it made; a disc's file opened to write alone is refused, and why a file is not opened is told as `DOS_OpenFile` tells it (`open_path`, `open_error`; `open.ts`).
- Both harnesses mount a probe's `iso` images (`image_volume`, `imageDrive`). [[probe:imgcd]] agrees wholly, 91 of 91 records, and [[probe:drvioctl]] 64 of 64, in both engines; [[probe:mscdex]] still 31 of 31.
- MSCDEX counts a drive removable and remote a CD-ROM, so a disc mounted answers 1500h and 150Bh as `imgcd` recorded.
- A disc's image is a `CdImage` (`crates/winbox-machine/src/files/cue.rs`, `src/file-systems/cue.ts`), `CDROM_Interface_Image`'s functions by their names: `set_device` / `setDevice` a cue sheet first, then one data track (`load_iso_file`); `load_cue_sheet` line by line as `getline` and `>>` read it; `add_track`; `get_track`; `read_sector`; each file a `BinaryFile` whose failed read fails it for good. An audio track's file is kept and not read, and its length not measured: a track after one is marked not `known`, and no sector is found past it. `IsoVolume::open` / `ISO9660.of(bytes, find)` take a function finding a sheet's files by the names it gives them: both harnesses look beside the sheet, in `oracle/probes/images/`, as `record.mjs` copies them there.
- [[probe:imgbin]], [[probe:imgcue]], [[probe:imgcue2]] and [[probe:imgtrk]] agree wholly, 91 of 91 records each, in both engines.
- The native build mounts a disc as `--mount D:game.cue` or `--mount D:game.bin` (`open_disc`, `crates/winbox-native/src/mounts.rs`), a sheet's files found as `GetRealFileName` finds them: as named, from the working folder, then beside the sheet. The page takes a `.cue` with the files it names dropped or chosen with it ([[topic:drives-and-disks]], "The page's drives").
- What a user with discs of their own should know: a sheet of one or more `BINARY` files whose first track is the data track, `MODE1/2352` or `MODE2/2352` -- the common rips, one `.bin` or a `.bin` to a track -- mounts; a lone `.bin` of 2,352-byte sectors mounts as it is. A sheet DOSBox refuses is refused, its line and why said: `line 3: GAME.BIN not found`, `line 1: DOSBox knows no command "ï»¿FILE"` (a byte-order mark; save the sheet without one), `DOSBox knows no track type "MODE2/2048"`. Where the data track is not first -- an enhanced CD, audio first -- there is no volume at sector 16, and the disc is refused as DOSBox refuses it. Audio tracks are not played.
- The page mounts a disc from its Drives strip, at the first free letter after the hard disks', and remembers a kept program's ([[topic:drives-and-disks]], "The page's drives"); [[probe:imgcd]] reads it there on both engines. The native build mounts one with `--mount D:GAME.ISO`, read from its file as sectors are asked for.

## Swapping a disc

DOSBox swaps a drive's discs -- `IMGMOUNT D A.ISO B.ISO` -- with its swap key, Ctrl+F4 ([[topic:drives-and-disks]], "Swapping a disk"). [[probe:imgswap]] swaps two while it has files open on the first and a search under way, and records what each call answers after the swap and after a second, back to the first:

- [[measured]] **A file open on a disc reads the disc in the drive now**, at its own sectors: `isoFile` reads through its drive's `readSector` (`drive_iso.cpp` 472-474), which asks MSCDEX's unit for the drive, and the disc swapped in points that unit at its own image (`Activate`, `UpdateMscdex`, 181-202). `BIG.DAT` opened on the first disc and read to byte 2,080 reads on, after the swap, `disc2 sector 2` from its third sector; seeked to its start, `disc2 sector 0`. `ONLY1.TXT`, opened on the first disc and not read, reads the 36 bytes of the second disc's `ONLY2.TXT`, which lies at the same sector, and its size stays the first's.
- [[measured]] **But for the sector it last read**, which the file keeps (`buffer`, `cachedSector`, 41-42, 71-74): the rest of `BIG.DAT`'s second sector, after the swap, still reads `disc1 sector 1`, and `SUB1\IN1.TXT`'s last 13 bytes are the first disc's. A seek leaves the sector kept: back on the first disc, `ONLY2.TXT` (opened on the second) seeked to its start reads `ONLY2.TXT line 1` again, and `BIG.DAT`, last reading the second disc's sector 0, reads it again from its start.
- [[measured]] 5700h answers the stamp the file was opened with; its size and where it is are its own (`fileBegin`, `fileEnd`).
- [[measured]] A search begun on the first disc and carried on after the swap (4Fh) ends with error 12h: its directory iterator's number is looked up among the second disc's (`FindNext`, 286-323, `dirIterators` per drive), whose iterator is not valid.
- [[measured]] The drive's current folder is kept, `D:\SUB1`, though the second disc has no `SUB1` (`CycleAllDisks`); a relative search there (`D:*.*`) answers error 3, and `SUB1` itself error 2 (4300h).
- [[measured]] The rest is the second disc's own: its label (`SWAPDISC.2`), its listing, its files by name (`ONLY1.TXT` error 2, `ONLY2.TXT` 21h). What is the drive's stays: 36h, IOCTL 4408h-440Eh, `GetDriveType`'s 4, MSCDEX's 150Bh and 1500h answer as before.

Both engines do the same (`DiscFile`, `iso.rs` and `iso9660.ts`; `Files::swap` and `FileManager.swap` hand each disc's file open on the drive the disc swapped in, `give_disc` / `giveDisc`), and [[probe:imgswap]] agrees wholly, 96 of 96, in both. Neither the native build nor the page needs more: each swaps through `Files::swap` or `FileManager.swap`. A disc taken out (WinBox's own, [[topic:drives-and-disks]]) leaves a file open on it nothing to read, as a sector not read: DOSBox has no such drive.

## Not yet done

- A write to a disc's file opened to read and write: DOSBox's `isoFile::Write` fails and DOS answers whatever error it last set (`dos.cpp` 590-603), which neither engine keeps; both answer 5.
- `DOS_MakeName` on a folder's drive, C: among them: both engines take any name there, cut nothing and refuse nothing, where DOSBox does as on an image.
- MSCDEX's calls that take a buffer (1501h, 1505h, 150Dh, 150Fh, 1510h), which through Windows need DPMI's real-mode calls and memory below 1 MB.
- CD audio: an audio track is kept, never played; MSCDEX's audio calls and the lengths of tracks in `WAVE`, `MP3` or `OGG` files, which DOSBox measures through `SDL_sound`. A track after such a file has no start known here, where DOSBox has one.
- A disc of audio tracks alone, which DOSBox mounts as a drive with no files labelled `Audio_CD` (`drive_iso.cpp` 167-174): both engines refuse it.
- `GetRealFileName`'s last try, a sheet's file named as a DOS path through DOSBox's own mounted folders: the native build has no counterpart for an image of the host's, and the page matches the files dropped with the sheet by name (and by the name's last part), without regard to case, where DOSBox on Linux minds it.
- An image of 2 GB or more: DOSBox's offsets are `int`, both engines' wider.
- What MSCDEX says of a disc swapped: its media-changed answer is the device driver's (1510h's IOCTL input, through `GetMediaStatus`, which answers `getSwapRequest()` -- FFh once after the swap key, else 01h, `dos_mscdex.cpp` 806-815), a buffer call neither engine makes. Unrecorded.
